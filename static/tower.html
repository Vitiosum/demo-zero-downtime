Journal de la tour

Ce que la tour a vu, à la milliseconde, depuis ce navigateur.

    Quatre scènes, la tour ouverte

    1. Déployer sans coupure

      cp releases/v2-bravo.json release.json
git commit -am "Release v2 Bravo"
clever deploy

      Clever Cloud démarre une nouvelle instance à côté de l'ancienne et attend que /health réponde 200. Les nouvelles connexions passent sur Bravo dans la seconde. Celle de cette page reste sur Alpha jusqu'à ce que Clever Cloud arrête Alpha, 2 minutes plus tard dans nos mesures, puis bascule sans erreur.

    2. Pousser une version cassée

      cp releases/v3-charlie-broken.json release.json
git commit -am "Release v3 Charlie"
clever deploy

      Charlie démarre, mais son /health répond 503. Clever Cloud réessaie en doublant le délai (2 s, 4 s… 512 s) sans lui envoyer de trafic, puis marque le déploiement en échec : 10 essais et 17 minutes dans nos mesures. Bravo sert pendant tout ce temps.

    3. Revenir à un commit précis

      clever restart --commit <commit d'Alpha>

      Le tableau « Qui répond » donne le commit de chaque release (bouton « copier »). Clever Cloud reprend le build de ce commit dans son cache, sans recompiler : 15 secondes jusqu'au health check dans nos mesures, puis la même bascule.

    4. Passer à deux instances

      clever scale --instances 2

      Clever Cloud démarre deux instances neuves depuis le cache de build, comme pour un déploiement, et arrête l'ancienne 2 minutes plus tard. Cochez « Nouveau visiteur » : les traits alternent entre deux hauteurs, une par instance. Retour à la plage : clever scale --min-instances 1 --max-instances 2.
