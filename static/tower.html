Journal de la tour

Ce que la tour a vu, à la milliseconde, depuis ce navigateur.

    Quatre scènes, la tour ouverte

    1. Déployer sans coupure

      cp releases/v2-bravo.json release.json
git commit -am "Release v2 Bravo"
clever deploy

      Clever Cloud démarre une nouvelle instance à côté de l'ancienne, attend que /health réponde 200, puis bascule le trafic. Bravo entre dans le ruban, Alpha s'efface, le compteur d'erreurs ne bouge pas.

    2. Pousser une version cassée

      cp releases/v3-charlie-broken.json release.json
git commit -am "Release v3 Charlie"
clever deploy

      Charlie démarre, mais son /health répond 503. Clever Cloud ne lui envoie aucune requête et marque le déploiement en échec. Bravo continue de servir.

    3. Revenir à un commit précis

      clever restart --commit <commit d'Alpha>

      Le tableau « Qui répond » donne le commit de chaque release. Clever Cloud redéploie ce commit, avec le même health check et la même bascule.

    4. Passer à deux instances

      clever scale --instances 2

      Une deuxième instance démarre et rejoint la répartition de charge. Les traits alternent entre deux processus. Retour à la normale : clever scale --min-instances 1 --max-instances 2.
